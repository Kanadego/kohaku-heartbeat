# 忙闲判定设计（v0.9 草案）· Busy-Detection

> 2026-08-31 与人类伙伴敲定 · 待审后实施
> 本文档是"环境温度计"从单信号升级为复合判定的设计稿。

## 0. 一句话

**键鼠退出忙闲判定；忙不忙 = 前台窗口类别 + 焦点窗口实时探查（15s 稳定窗）。**

## 1. 信号分工总表

| 信号 | 来源 | 用途 | 隐私 |
|------|------|------|------|
| 键鼠空闲秒数 | idle.ps1（GetLastInputInfo） | 两档兜底：离开 / 空闲 | 仅一个数字 |
| 前台窗口 | screenpulse（GetForegroundWindow） | 类别判定（忙/闲）| 标题+进程加密 |
| 焦点窗口 | 新增（GetGUIThreadInfo.hwndFocus） | 实时活跃判定 | 标题+进程加密 |
| 可见窗口列表 | 新增（EnumWindows + IsWindowVisible） | 后台挂载观测（最多 20 个）| 标题+进程加密 |
| 屏幕截图 | screenpulse（已存在） | 兜底：离开 vs 看电影 | DPAPI 加密、用时解锁即焚 |

## 2. 键鼠规则（简化版）

| idle 秒数 | 判定 | 说明 |
|-----------|------|------|
| ≥ 1200s（20 分钟） | **离开或看电影** | 解锁截图区分：电影画面→陪伴型观看；空桌面/锁屏→离开 |
| 30s ~ 1200s | **空闲** | 人还在，未密集操作，可开口 |
| < 30s | 不直接判忙 | 键鼠不参与繁忙判定，忙闲交给窗口类别 |

## 3. 前台窗口类别表

| 类别 | 判定 | 判定依据 |
|------|------|---------|
| 游戏（全屏） | **繁忙** | 窗口矩形 == 屏幕 Bounds |
| 游戏（窗口化） | 空闲 | 窗口矩形 < 屏幕 |
| 办公/文档（Word/Excel/WPS…） | **繁忙** | 应用类别映射 |
| IDE/编辑器/终端 | **繁忙** | 类别映射（IDEA/VSCode/PowerShell…）|
| 会议/直播（teams/zoom/obs…） | **繁忙** | 类别映射 |
| 全屏视频（电影/直播观看） | 空闲 | 用户保留吐槽位，特批 www |
| 图像/剪辑/创作 | 空闲 | 类别映射 |
| 浏览器/资源管理器 | 空闲 | 默认 |

类别表为**可配置映射**（config 驱动，非硬编码），方便人类伙伴与其朋友按自己机器调整。

## 4. 实时活跃判定（开口前探查）

- **时机**：gate 决定是否开口的那一刻实时采集，不用 2h 心跳快照（快照只用于记录，不用于决策）
- **机制**：读取前台线程的焦点窗口（GetGUIThreadInfo.hwndFocus）
- **稳定窗**：焦点窗口需连续稳定 ≥ 15 秒才采信为"活跃"——防"切过去点两下就切走"的瞬时误判
- **组合**：前台稳定 + 焦点窗口类别 = 忙闲裁决

## 5. 可见窗口列表（后台挂载观测）

- 采集：EnumWindows + IsWindowVisible（任务栏级），标题 + 进程名，DPAPI 加密入库
- 上限：20 个窗口，超限截断（控 token 与存储）
- **不采集**：托盘图标（最小化到托盘的程序不可见，接受盲区）；不枚举全部进程

## 6. 隐私契约更新（超越零枚举）

原宪章"只采前台窗口、零枚举"正式修订为：
- **可见窗口级枚举**（有上限、非全进程）
- 标题/进程全部 DPAPI 加密入库，明文即焚
- 焦点窗口只在开口决策时读取，不落历史
- 所有采集不进模型请求上下文（只存快照、按需读）→ token 成本趋零
